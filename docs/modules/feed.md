# Feed

Manages YAML-defined product feeds built on the [export](export.md) module's source reader and targets. There are two templates: a generic CSV feed and a Google Merchant RSS 2.0 feed. The module adds required-field validation, preview and export (CLI and admin), and an optional tokenized public URL for shopping engines.

Config key: `elevate_dxp.feed` · Permission: `elevate_dxp_feed` · Admin menu: Elevate DXP → Marketing

Installed with the bundle; no tables (permission only).

## Configuration

```yaml
elevate_dxp:
    feed:
        enabled: true          # false: export refused, public URLs answer 404
        chunk_size: 100        # listing page size (min 1)
        feeds:
            google_shopping:                         # name: [A-Za-z0-9_-]+
                source: { type: data_object, class: Product }   # data_object | asset (required)
                template: google_merchant            # generic_csv | google_merchant (required)
                currency: EUR                        # default EUR
                link_pattern: 'https://shop.example.com/p/{id}'  # optional, default null
                mappings: { id: sku, title: name, description: description, image_link: imageUrl, price: price, availability: availability }
                static: { condition: new, brand: ACME }
                channel: { title: Shop, link: 'https://shop.example.com', description: Products }
                target: { type: local, path: feeds/google.xml }  # local | asset | http
                token: '%env(FEED_GOOGLE_TOKEN)%'    # enables the public URL; min 16 chars
                cache_ttl: 300                       # seconds; 0 = render on every request
```

- `mappings` is `feed field => source accessor`, resolved by the core field mapper (see [export.md](export.md#source)).
- `static` fills a field only when it is missing or empty after mapping.
- `link_pattern`, when set, always overwrites `link`. `{field}` placeholders refer to feed fields (after mappings and static values).
- `channel` defaults: title `Product feed`, link `https://example.com`, description `Generated by Elevate DXP`. The channel is used only by `google_merchant`.
- `target.type` defaults to `local`. `target.path` defaults to `<name>.<csv|xml>`. Targets are the export targets, so a `local` path resolves under `elevate_dxp.export.base_path` (default `var/elevate-dxp/exports`).

## Templates

| Template | Output | Required fields |
|---|---|---|
| `generic_csv` | CSV via the export `CsvRenderer` (same formula-injection guard), `text/csv` | `id`, `title` |
| `google_merchant` | RSS 2.0 with the `g:` namespace, `application/rss+xml` | `id`, `title`, `description`, `link`, `image_link`, `availability`, `price` |

For `google_merchant`:

- `title`, `link` and `description` have no prefix. Every other field is emitted as `g:<field>`.
- `price` and `sale_price` are formatted as `12.99 EUR` using `currency`, unless the value already ends with a 3-letter uppercase code. A non-numeric price becomes `0.00`.

Validation flags rows where a required field is missing or empty. It does not block an export. The export reports the number of rows with issues.

## Public URL

`GET|HEAD /elevate-dxp/feed/{name}.{format}?token=...` (route `elevate_dxp_feed_public`, outside `/admin`). `format` is `csv` or `xml` and must match the template. The token can also be sent in the `X-Elevate-Dxp-Feed-Token` header. The query parameter takes precedence.

- **Deny-by-default:** a feed is served only if it has a token of at least 16 characters. The token is compared with `hash_equals`.
- **Uniform denial:** an unknown feed, a disabled module, a missing or wrong token and a format mismatch all return the same `404 Not found.`, so feed names cannot be enumerated. No feed data is read for a denied request.
- **Success headers:** `Cache-Control: max-age=0, private`, `X-Robots-Tag: noindex, nofollow`, `Referrer-Policy: no-referrer` and `Content-Disposition: inline; filename="<name>.<format>"`.
- **Errors:** a rendering error returns a plain-text `503`.
- **Caching:** the rendering is cached in `cache.app` under `edxp_feed_<name>` for `cache_ttl` seconds. Data changes and admin or CLI exports do not invalidate it.
- **Audit:** every request is logged as `feed.<name>.public` with status `ok` (rows), `denied` (reason) or `error`. The actor is `token:<first 12 hex chars of the token's sha256>`, never the token itself.

The token sits in the URL, so it can end up in proxy and access logs. Rotate it by changing the environment variable. See [../security-and-privacy.md](../security-and-privacy.md).

### Web server

Public feed URLs end in `.csv` or `.xml`. The official OpenDXP nginx example does not list these extensions in its static-file location. If your config adds `csv` or `xml` there, add `/elevate-dxp/` to the negative lookahead, or nginx returns 404 without reaching PHP:

```nginx
location ~* ^(?!/admin|/asset/webdav|/elevate-dxp/)(.+?)\.((?:css|js)(?:\.map)?|jpe?g|gif|png|svgz?|eps|exe|gz|zip|mp\d|m4a|ogg|ogv|webp|webm|pdf|csv|xml|docx?|xlsx?|pptx?)$ {
    try_files /var/assets$uri $uri =404;
    # ... rest unchanged
}
```

See also [../../README.md#6-web-server](../../README.md#6-web-server).

## Admin

**Product feeds** (`feeds`) is a read-only grid with columns for template, source, class, currency, target, whether a public URL exists and its path (the token is never shown), link pattern, mappings and static values. Record actions:

- **Validate:** builds the full feed and returns a table of rows with missing required fields, or a success message.
- **Preview:** parameters `limit` (default 20, max 200) and `as` (`table` with a `_missing` column per row, or `rendered`).
- **Export** (asks for confirmation): renders the feed and writes it to its target.

## CLI

```
bin/console elevate-dxp:feed:preview <feed> [--limit=10]   # rows + validation issues
bin/console elevate-dxp:feed:export <feed>                 # render and write to the target
```

Exports are audited as `feed.<name>` with status `export` (rows, issues, location) or `failure`. Like export jobs, a feed export takes an exclusive, non-blocking lock per feed (`flock` on `edxp_feed_<name>.lock` in the system temp dir): a second export of the same feed, from the CLI or the admin, fails immediately with "already being exported" instead of interleaving its writes. Different feeds run in parallel. The lock is per host; the public feed URL only renders and takes no lock.
