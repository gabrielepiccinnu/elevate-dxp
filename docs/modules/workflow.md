# Workflow

A designer for the native OpenDXP (Symfony Workflow) engine. Definitions are stored as YAML files (GitOps-friendly), validated, previewed as Mermaid diagrams, exported and imported as constrained BPMN 2.0, and applied as `opendxp.workflows` configuration files.

Config key: `elevate_dxp.workflow` · Permission: `elevate_dxp_workflow` · Admin menu: Elevate DXP → Content

See also: [Configuration](../configuration.md), [Architecture](../architecture.md), [Security and privacy](../security-and-privacy.md).

## Installation

The bundle installer (`bin/console opendxp:bundle:install ElevateDxpBundle`) registers the permission. The module creates no tables. Optional demo definition:

```bash
bin/console elevate-dxp:workflow:demo-seed   # stores "product_review" and prints its Mermaid diagram
```

## Configuration

Defaults shown:

```yaml
elevate_dxp:
    workflow:
        enabled: true                               # currently not read by any service
        storage_dir: var/elevate-dxp/workflows      # designer definitions, relative to the project dir
        apply_dir: config/local                     # where "apply" writes elevate_dxp_workflow_<name>.yaml
        mermaid_render_url: 'https://mermaid.ink/svg/'   # null = no external rendering
```

The standard OpenDXP `config/config.yaml` imports `local/`, so applied files are loaded automatically. `apply_dir` must be writable by the PHP user. Either keep `config/local` out of version control and apply per environment (committing only the YAML under `storage_dir`), or point `apply_dir` to a committed directory that your config imports.

## Definition format

Stored as `<storage_dir>/<name>.yaml`:

```yaml
name: product_review          # starts with a letter; letters, digits, underscore; max 64
label: Product review
subject: Product              # DataObject class name, or a fully qualified class
type: state_machine           # or "workflow" (parallel places)
initial_place: draft          # defaults to the first place
places: [draft, in_review, approved, rejected]
transitions:
  submit:  { from: [draft], to: in_review }
  approve: { from: [in_review], to: approved, guard: "is_granted('ROLE_OPENDXP_ADMIN')", notifyRoles: [Editor] }
  reject:  { from: [in_review], to: rejected, commentRequired: true }
placeMeta:
  approved: { title: Approved, color: '#52c41a', lockEditing: true }
```

`commentRequired: true` implies `commentEnabled: true`.

The validator checks: name pattern; subject class syntax; at least one place, no empty or duplicate places; the initial place exists; at least one transition; every transition has at least one `from` place and all `from`/`to` places exist; `placeMeta` only references existing places; colours are hex (`#rgb` or `#rrggbb`). Saving, importing and applying reject invalid definitions.

## Apply

Apply writes `<apply_dir>/elevate_dxp_workflow_<name>.yaml` (see `WorkflowConfigWriter::path()`), shaped for `OpenDxp\Bundle\CoreBundle\DependencyInjection\Configuration::addWorkflowNode()`:

```yaml
# Generated by the Elevate DXP workflow designer — do not edit by hand.
opendxp:
    workflows:
        product_review:
            label: Product review
            type: state_machine
            supports: ['OpenDxp\Model\DataObject\Product']
            places:
                approved: { title: Approved, color: '#52c41a', permissions: [{ modify: false }] }
                # ...
            initial_markings: [draft]
            transitions:
                approve:
                    from: [in_review]
                    to: approved
                    guard: "is_granted('ROLE_OPENDXP_ADMIN')"
                    options: { label: approve, notificationSettings: [{ notifyRoles: [Editor], channelType: [mail] }] }
                reject:
                    from: [in_review]
                    to: rejected
                    options: { label: reject, notes: { commentEnabled: true, commentRequired: true } }
```

- `options` is always emitted, because the OpenDXP workflow compiler pass reads it directly.
- `lockEditing` becomes `permissions: [{ modify: false }]` on the place.
- No marking store is written, so the OpenDXP default applies.
- Workflows are compiled into the container: run `bin/console cache:clear` after apply or un-apply. The admin messages and the CLI remind you.

The apply status is `applied` (file content equals the current rendering), `outdated` (file differs) or `not_applied` (no file).

## Admin resource `workflows`

Crud resource ("Workflow designer") keyed by `name`. The form edits name, label, subject class, type and initial place, plus a code field "Places & transitions (YAML or JSON)" holding `places`, `transitions` and `placeMeta`. Saving under an existing name overwrites it. The grid shows place and transition counts, the validation result and the apply status.

| Action | Scope | Result |
|---|---|---|
| Validate | record | message, or a table of errors |
| Preview (Mermaid) | record | HTML: an `<img>` rendered by `mermaid_render_url` (omitted when null), an "Open in Mermaid Live Editor" link, validation errors, and the Mermaid source |
| Export BPMN | record | BPMN 2.0 XML with DI layout (`<name>.bpmn`) |
| Show OpenDXP config | record | the YAML that apply would write |
| Apply | record | validates, writes the file, reminds you to run `cache:clear` |
| Un-apply | record | removes the file; fails if it was not applied |
| Import BPMN | global | params: name (optional, defaults to the process id) and XML; mapped, validated and stored |
| Create demo workflow | global | stores `product_review`; fails if it already exists |

Privacy: the preview image URL contains the base64-encoded Mermaid source (place and transition names), so it is sent to `mermaid_render_url`; the Live Editor link sends it to mermaid.live when clicked. Set `mermaid_render_url: null` or point it to a self-hosted renderer to keep diagrams internal.

## BPMN mapping (constrained)

- `bpmn:process`: `@id` is the workflow name, `@name` the label.
- `bpmn:task` is a place (name = `@name`, fallback `@id`).
- A sequence flow from a `startEvent` to a task marks the initial place (fallback: first place).
- A task → task sequence flow is a transition (name = `@name`, fallback `@id`). Flows sharing a name are merged into one transition with several `from` places.
- Gateways, other events and sub-processes are ignored.
- Extension attributes use the namespace `http://elevate-dxp/bpmn` (prefix `elevatedxp`): `type` and `subject` on the process; `title`, `color`, `lockEditing` on tasks; `guard`, `commentEnabled`, `commentRequired`, `notifyRoles` (comma-separated) on flows. Defaults: `state_machine`, `Product`.
- Import rejects documents larger than 2,000,000 bytes and any `DOCTYPE`, and parses with `LIBXML_NONET`.

## CLI

| Command | Description |
|---|---|
| `elevate-dxp:workflow:list` | definitions with validation and apply status |
| `elevate-dxp:workflow:demo-seed` | stores `product_review` (overwrites an existing one) and prints its Mermaid diagram |
| `elevate-dxp:workflow:apply <name>` | validates and writes the config file, like the admin action; run `cache:clear` afterwards |

There is no CLI un-apply; delete the file under `apply_dir` or use the admin action.
